# How Drawings Become Citizens of a Second Brain

## Summary

ภาพวาดจะกลายเป็น "พลเมือง" ของสมองที่สองได้ก็ต่อเมื่อมันอยู่ในระบบไฟล์เดียวกับโน้ต — ฝังได้ ลิงก์ได้สองทาง และซ้อนกันได้ — ไม่ใช่ภาพโดดเดี่ยวในแอปแยก: วิดีโอ Excalidraw ของ Karlos (ปลั๊กอินอันดับ 1 ของ Obsidian, 5,451,903 ดาวน์โหลด, ภาพหน้าจอ [00:05] ในคลิป) [[excalidraw-visual-thinking-karlos|สาธิตกลไกครบชุดที่ทำให้เป็นเช่นนั้น]] พร้อมเงื่อนไขสำคัญคือต้องเรียนรู้พื้นฐาน Obsidian ก่อน ไม่งั้นเสียศักยภาพไป ~90% ความตึงของคำตอบ: เสรีภาพเชิงพื้นที่ (วาดอะไรก็ได้ วางตรงไหนก็ได้) กับวินัยของระบบ (ลิงก์/ฝังต้องมาก่อน ไม่งั้นภาพก็ยังโดดเดี่ยวอยู่ดี)

## 1. ปัญหาที่วิดีโอตั้งไว้: ภาพโดดเดี่ยว

Karlos เปิดคลิปด้วยข้อโต้แย้งเรื่องค่าใช้จ่ายที่ไร้ผล: เขาใช้ Notability และ OneNote หลายปี (Notability Plus $20/ปี, Pro $99/ปี; Microsoft 365 $9.99–19.99/เดือน) แต่แต่ละภาพวาดถูกเก็บอย่างโดดเดี่ยว — ไม่เชื่อมโยงถึงกันและไม่เชื่อมกับระบบสมองที่สองใน Obsidian [[excalidraw-visual-thinking-karlos]] จุดต่างของ Excalidraw ตามที่เขาบอกคือเป็นของฟรีที่ครอบครองไฟล์ได้ตลอดไป และภาพเชื่อมกับโน้ตได้หมด ข้อโต้แย้งนี้คือรากของคำถามทั้งหน้า: อะไรทำให้ภาพ "อยู่ในระบบ" ไม่ใช่แค่ "อยู่ในแอป"

## 2. กลไกการเป็นพลเมือง: ฝัง, ลิงก์สองทาง, ซ้อน

วิดีโอสาธิตกลไก 3 ชั้นที่ทำให้ภาพเป็นส่วนหนึ่งของ vault [[excalidraw-visual-thinking-karlos]]:

- **ฝัง (embed)** — พิมพ์ `![[ชื่อกระดาน]]` ในโน้ต ภาพกระดานเรนเดอร์แทรกในข้อความแบบ real-time (แก้กระดานแล้วโน้ตอัปเดตตามทันที), ปรับขนาดด้วย `|800` ต่อท้ายลิงก์, และมีทางลัด Command Palette เพื่อฝังกระดานล่าสุด
- **ลิงก์สองทาง (bidirectional)** — ลากโน้ตจาก File Explorer ลงกระดานเป็นกล่องลิงก์, คลิกขวารูปทรงแล้ว Add link, และ Copy link for the selected element(s) เพื่อได้ deep link ที่พุ่งไปโฟกัสชิ้นนั้นบนกระดาน; Group Link ฝังได้เฉพาะพื้นที่ส่วนหนึ่งของกระดานลงในโน้ต
- **ซ้อน (nesting)** — นำกระดาน .excalidraw อีกอันมาฝังในกระดานปัจจุบัน แก้กระดานย่อยแล้วกระดานใหญ่อัปเดตตาม — ย่อยไอเดียใหญ่เป็นชิ้นเล็กแล้วรวมเป็นภาพใหญ่

ชั้นเสริม: ฝัง GIF แบบ embeddable (ไม่ใช่ image ซึ่งจะนิ่ง), PDF สองโหมด (as image สำหรับ annotate / embeddable สำหรับอ่าน), interactive web frame (ลาก URL แล้วกด Option/Alt), live markdown embed ที่พิมพ์แก้ในกระดานได้ และระบบอ้างอิงไฟล์อัจฉริยะ — ย้าย/เปลี่ยนชื่อไฟล์แล้วการอ้างอิงทุกจุดอัปเดตตาม [[excalidraw-visual-thinking-karlos]]

## 3. เงื่อนไขก่อน: "กับดักใหญ่" ของมือใหม่

Karlos เตือนชัดว่า กับดักที่คนส่วนใหญ่พลาดคือข้ามพื้นฐาน Obsidian แล้วพุ่งไปวาดรูปเลย ซึ่งเสียศักยภาพของ Excalidraw ไปถึง ~90% [[excalidraw-visual-thinking-karlos]] พื้นฐานที่เขาหมายถึงคือสองอย่าง: wikilinks (ลิงก์สองวงเล็บเหลี่ยมที่เชื่อมโน้ตถึงกัน) และ embeds (เครื่องหมายตกใจหน้าลิงก์ที่ดึงเนื้อหาโน้ตมาแสดง) — การอ่านเชิงวิเคราะห์: กลไกทั้งชุดในหัวข้อ 2 วิ่งอยู่บนกลไก links/embeds ของ Obsidian ทั้งสิ้น ภาพจึง "เป็นพลเมือง" ได้เพราะแพลตฟอร์มเจ้าบ้านมีภาษาเชื่อมโยงอยู่ก่อนแล้ว ไม่ใช่เพราะตัวปลั๊กอินวาดรูป

## 4. รากฐานไฟล์: หนึ่งไฟล์สองหน้า

ความจริงที่ทำให้ทุกอย่างข้างต้นเป็นไปได้คือโครงสร้างไฟล์: กระดาน Excalidraw คือไฟล์ Markdown จริงๆ — เปิด "Open as markdown" จะเห็นโค้ดข้อมูลวาดรูป ตามด้วยข้อความ "back of note card" ที่พิมพ์ไว้หลังกระดาน [[excalidraw-visual-thinking-karlos]] แนวคิด back of note card คือการพลิกการ์ดกายภาพ: วาดรูปด้านหน้า เขียนสรุปความคิดด้านหลัง — ภาพกับข้อความอยู่ในไฟล์เดียวกัน แก้ฝั่งไหนอีกฝั่งอัปเดตตาม ดังนั้น "ภาพ" กับ "โน้ต" ไม่ใช่คู่ต่างไฟล์ที่ต้องบริหารการซิงก์ แต่เป็นหน้าสองหน้าของ artifact เดียวกัน

## 5. สังเคราะห์: เกณฑ์การเป็นพลเมือง

ชั้นวิเคราะห์ของสังเคราะห์นี้ (ต่อจากข้อเท็จจริงในวิดีโอ ไม่ใช่ข้อความตรงจากคลิป): จากกลไกในหัวข้อ 2–4 เกณฑ์ที่ทำให้ภาพวาดเป็นพลเมืองของสมองที่สอง มี 3 ข้อ — (1) อยู่ใน namespace เดียวกับโน้ต (ไฟล์ใน vault ที่ค้นหาและอ้างอิงได้), (2) ลิงก์ได้สองทางระดับ element (ทั้งโน้ต→กระดานและกระดาน→โน้ต, ละเอียดถึงชิ้นส่วนเดียว), (3) มีโหมด "เขียน" ต่อท้ายภาพ (back of note card) ทำให้ภาพรับข้อความสรุปได้ในตัว เมื่อครบสามข้อ ภาพจึงเป็นโหนดในกราฟความรู้ ไม่ใช่ไฟล์แนบ สมการตรงข้ามคือกรณี Notability/OneNote: ภาพอยู่ในแอปแยก (ผิดข้อ 1), ลิงก์ข้ามภาพไม่ได้ (ผิดข้อ 2), และไม่มีพื้นที่โน้ตผูกกับภาพ (ผิดข้อ 3) — นี่คือเหตุผลเชิงโครงสร้างที่วิดีโอสรุปว่า "เปลืองเงินเปล่า"
